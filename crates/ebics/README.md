# ebics

[![crates.io](https://img.shields.io/crates/v/ebics.svg)](https://crates.io/crates/ebics)
[![docs.rs](https://docs.rs/ebics/badge.svg)](https://docs.rs/ebics)

EBICS 3.0 for corporate banking: the H004 messages and the cryptography a client needs.

EBICS is the protocol a European company uses to send payment files to its bank and to fetch statements. It is XML over HTTPS, but the XML is only half of it: every message is signed with RSA and, for order data, encrypted with AES under a key the bank wraps for the customer. This crate is both halves.

It is deliberately self-contained. The workspace policy is Apache-2.0 with no external crates, so the RSA, AES, SHA-256, DEFLATE, base64 and canonical XML are all implemented here rather than pulled in. That is a real cost, and it is paid because a banking client that cannot be audited line by line is not worth shipping.

## What is verified, and against what

Cryptography that only agrees with itself proves nothing, so each layer is checked against an independent implementation:

| Layer | Checked against |
| --- | --- |
| SHA-256 | FIPS 180-4 vectors |
| AES-128 | FIPS 197 appendices B and C, NIST SP 800-38A |
| RSA PKCS#1 v1.5 and PSS | Python `cryptography`, both directions |
| Canonical XML | a request generated by `node-ebics-client` |
| Signatures | Python `cryptography` accepts what this crate signs |
| Order data | a response built by Python, decrypting back to the original |

The header digest reproduces, byte for byte, the digest that `node-ebics-client` put in its own message. That is the check that matters most: a digest that is right by this crate's own reckoning but wrong by the bank's is a client that silently cannot log in.

## Signing a request

```rust
use ebics::header::{OrderAttribute, StaticHeader};
use ebics::message::{Request, RequestKind, verify};
use ebics::rsa::PrivateKey;

# const MODULUS: &str = "2aWRwQ9/pII5l29p55PIXEWlJsvSn/d5KOpz/wnUEJ9AZvq2CitcgYhCG0qqn8Eb3G61qqQfNONhHUPdzc8Fndnv0Uqzg+Xtz4kSjHWZQZb069Po6jgLwUbmuuyfdlQpU4GdyrPHtFTd18tP20/5pmic1ui+9GQnyRBhoh55CTU=";
# const EXPONENT: &str = "AQAB";
# const PRIVATE: &str = "M1NfRvb/s+zd5f9pKypnopLt+nMwjXbPxL1dc3R+5RiZGG/hRA6rtwRKCqOWDyx8BIS7JK2lilRgz4T0ppc+jGbF3FIaqLzrr7b5hQJN97vR1f5PYZxGXQppx2qto2tQbm9Ct6K8UmRQTAI33ndB0yjhTUzXJnxl/lKnuBX0O/U=";
# fn main() -> Result<(), Box<dyn std::error::Error>> {
// The subscriber key the bank has on file.
let key = PrivateKey::from_base64(MODULUS, EXPONENT, PRIVATE)?;

// The nonce must be fresh for every request, or the bank refuses the replay.
let mut rng = ebics::rng::Rng::from_entropy();
let nonce = rng.bytes(16).iter().map(|b| format!("{b:02x}")).collect::<String>();

let header = StaticHeader::signed(
    "HOST", "PARTNER", "USER", "HPB",
    OrderAttribute::WithoutSignatureCompressedEncrypted,
    nonce,
)?;

// `sign` builds the document, digests the header and signs `ds:SignedInfo`.
let xml = Request::new(RequestKind::NoPubKeyDigests, header).sign(&key)?;

// What the bank does with it: recompute the digest, then check the signature.
verify(&xml, key.public())?;
assert!(xml.contains("<ds:SignatureValue>"));
# Ok(())
# }
```

## Reading a response

```rust
use ebics::response::Response;

# fn main() -> Result<(), Box<dyn std::error::Error>> {
# let body = r#"<ebicsKeyManagementResponse xmlns="urn:org:ebics:H004" Version="H004" Revision="1"><header authenticate="true"><static></static><mutable><ReturnCode>000000</ReturnCode><ReportText>[EBICS_OK] OK</ReportText></mutable></header><body><ReturnCode authenticate="true">000000</ReturnCode></body></ebicsKeyManagementResponse>"#;
// A refusal becomes an `Err`, so `?` is enough to stop on one.
let response = Response::parse(body)?.into_result()?;
assert!(response.is_success());
# assert_eq!(response.technical_code, "000000");
# Ok(())
# }
```

## What is here

- `header`, `message`, `response` - the H004 messages, their signatures, and the order data inside them
- `rsa` - key digests, PKCS#1 v1.5 sign and verify, PSS, key wrapping
- `aes` - AES-128-CBC with the zero IV and the EBICS padding
- `sha256`, `base64`, `flate`, `bignum`, `rng` - the primitives, with no external crates
- `c14n` - the canonical XML the digests are taken over
- `returncodes` - the technical and business return codes, and what they mean
- `time` - the header timestamp format
